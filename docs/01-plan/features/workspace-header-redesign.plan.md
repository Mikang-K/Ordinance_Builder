# 작업 화면 상단 바 UI 개선 계획

- 작성일: 2026-07-28
- 상태: Planning
- 대상: `frontend`
- 구현 단계: 미착수

## 1. 배경과 문제

현재 작업 화면의 `app-header`에는 다음 요소가 한 영역에 동시에 배치된다.

- 서비스 브랜드와 설명
- 현재 작업명
- 글자 크기 조절
- 7단계 진행 표시
- AI 모델 상태
- 조문/초안/확정본 다시 열기
- 새 조례 만들기
- 도움말
- 목록 이동
- 사용자 정보와 로그아웃

데스크톱에서는 3열 그리드 한 줄 안에서 요소들이 폭을 경쟁하고, 일부 항목은 여러 줄로 감긴다. 태블릿부터는 진행 단계가 두 번째 줄로 이동하지만 나머지 작업 버튼이 여전히 조밀하다. 모바일에서는 작업 버튼 전체를 가로 스크롤로 제공해 중요한 동작이 화면 밖에 숨을 수 있다.

핵심 문제는 헤더 높이 자체보다 서로 성격이 다른 정보와 동작이 같은 시각적 레벨에 놓여 있다는 점이다.

## 2. 목표

- 헤더를 2단 구조로 재편해 정보와 동작의 우선순위를 명확히 한다.
- 현재 조례명과 현재 진행 단계를 가장 쉽게 인식할 수 있게 한다.
- 자주 쓰는 문맥 동작과 전역 동작을 시각적으로 분리한다.
- 화면 폭이 줄어도 버튼이 무작위로 감기거나 잘리지 않게 한다.
- 헤더 높이를 적절히 늘리되 실제 작업 영역을 과도하게 침범하지 않는다.
- 기존 기능, 라우팅, 모달 및 튜토리얼 target ID를 유지한다.

## 3. 제안 구조

### 첫째 줄: 작업 식별과 전역 제어

```text
[브랜드]  [현재 작업 · 조례명]                [AI 상태] [글자 크기] [사용자 메뉴]
```

- 왼쪽: 브랜드는 제목 중심으로 축소하고 긴 부제는 데스크톱에서만 보조 정보로 표시
- 중앙: 현재 작업명을 독립적인 제목 영역으로 승격
- 오른쪽: AI 상태, 글자 크기, 사용자/로그아웃 등 전역 설정 배치

### 둘째 줄: 진행 상태와 작업 동작

```text
[목록으로]  [7단계 진행 표시]                 [문맥 동작] [새 조례] [도움말]
```

- 왼쪽: “목록”을 뒤로가기 성격이 분명한 보조 버튼으로 배치
- 중앙: 진행 표시가 충분한 가로 폭을 사용하도록 확장
- 오른쪽: 현재 단계에 따라 나타나는 조문 편집·초안 검증·확정본 보기 버튼과 새 작업/도움말 배치

첫 줄과 둘째 줄 사이에는 약한 구분선 또는 배경 명도 차이를 사용한다. 완전히 다른 두 개의 헤더처럼 보이기보다는 하나의 작업 도구막대 안에서 계층만 구분한다.

## 4. 정보 우선순위

| 우선순위 | 요소 | 처리 |
| --- | --- | --- |
| P0 | 현재 작업명 | 항상 표시, 충분한 폭 확보, 긴 이름은 말줄임표와 전체 이름 접근 수단 제공 |
| P0 | 진행 단계 | 둘째 줄 중심 영역에 고정 |
| P0 | 현재 단계의 문맥 동작 | 조문 편집·초안 검증·확정본 보기 중 해당 항목만 강조 |
| P1 | 목록 이동 | 항상 표시 |
| P1 | 새 조례 만들기 | 항상 표시하되 현재 작업 동작보다 낮은 시각적 강조 |
| P1 | AI 모델 상태 | 첫 줄 우측에 간결하게 표시 |
| P2 | 글자 크기 | 첫 줄 우측 설정 그룹 |
| P2 | 도움말 | 전역 보조 동작으로 처리 |
| P2 | 사용자 정보·로그아웃 | 사용자 메뉴 또는 간결한 계정 영역으로 묶음 |
| P3 | 서비스 부제 | 좁은 화면에서 숨김 |

## 5. 화면 크기별 동작

### 데스크톱: 1200px 이상

- 헤더를 명시적인 2행 grid로 구성
- 권장 전체 높이: 약 116~132px
- 첫째 줄은 48~56px, 둘째 줄은 52~60px
- 진행 표시가 둘째 줄의 가장 넓은 영역을 차지
- 모든 주요 버튼을 직접 노출

### 태블릿: 768~1199px

- 동일한 2단 개념 유지
- 첫째 줄의 부제 숨김
- 사용자 이름은 축약하거나 아바타 중심으로 표시
- 글자 크기 컨트롤은 폭을 줄이되 조작 가능한 크기 유지
- 둘째 줄은 진행 표시와 동작 영역을 분리해 필요하면 동작만 다음 행으로 내려 총 3행까지 허용
- 자동 줄바꿈 순서를 CSS `order`에 의존하지 않고 명시적인 컨테이너로 관리

### 모바일: 767px 이하

- 가로 스크롤 작업 버튼 줄을 제거하는 방향을 우선 검토
- 첫째 줄: 목록 버튼, 현재 작업명, 사용자/메뉴
- 둘째 줄: 축약된 진행 표시
- 셋째 줄: 현재 단계의 핵심 문맥 동작 1개와 “더보기” 메뉴
- 새 조례, 도움말, AI 상태, 글자 크기, 로그아웃은 더보기 메뉴 또는 설정 패널로 묶기
- 터치 영역 최소 44px 유지

모바일 더보기 메뉴를 도입하지 않는 최소 구현안에서는 핵심 동작을 첫 위치에 두고 나머지만 가로 스크롤하도록 개선할 수 있으나, 최종안은 숨은 동작 발견성과 접근성 측면에서 메뉴 방식을 권장한다.

## 6. 컴포넌트 설계

현재 헤더 JSX가 `App.tsx`에 직접 포함되어 있으므로 별도 컴포넌트로 추출한다.

```text
WorkspaceHeader
├─ HeaderIdentity
│  ├─ Brand
│  └─ CurrentOrdinance
├─ HeaderUtilities
│  ├─ ModelStatus
│  ├─ FontSizeControl
│  └─ UserMenu
├─ HeaderNavigation
│  └─ BackToList
├─ HeaderProgress
│  └─ StageIndicator
└─ HeaderActions
   ├─ ContextAction
   ├─ NewSession
   └─ Help
```

`WorkspaceHeader`에는 화면 상태 전체가 아니라 표시와 동작에 필요한 값만 props로 전달한다.

- `ordinanceType`
- `stage`
- `fontSize`, `onFontSizeChange`
- 문맥 동작의 표시 여부와 callback
- `onNewSession`, `onTutorial`, `onBackToList`, `onLogout`
- 사용자 표시 정보

문맥 버튼 조건은 현재 `App.tsx` 로직을 유지하되 헤더 컴포넌트에서 임의로 워크플로 상태를 변경하지 않는다.

## 7. 시각 설계 지침

- 배경색은 기존 `#1e40af` 계열을 유지해 전체 리디자인 범위를 피한다.
- 첫째 줄은 브랜드/작업 식별, 둘째 줄은 작업 진행을 강조하도록 명도 또는 테두리 차이를 준다.
- 현재 조례명은 작은 “현재 작업” 레이블과 본문 제목의 수직 구조로 표시한다.
- 버튼 계층:
  - Primary: 현재 단계의 문맥 동작
  - Secondary: 새 조례, 목록
  - Tertiary: 도움말, 설정, 로그아웃
- 조건부 문맥 버튼의 색상을 상태별로 무분별하게 바꾸지 않고 한 가지 강조 체계로 통일한다. 완료 결과 보기는 성공 의미를 보조 아이콘/배지로 표현할 수 있다.
- 버튼 텍스트와 아이콘을 함께 사용할 경우 아이콘만으로 의미를 전달하지 않는다.
- 지나친 그림자 대신 구분선, 투명 배경, 간격으로 계층을 만든다.

## 8. 접근성 요구사항

- 헤더 내부에 `nav` 또는 적절한 `aria-label`로 목록 이동과 작업 동작 그룹을 구분
- 현재 진행 단계의 `aria-current="step"` 유지
- 사용자 메뉴는 `aria-expanded`, `aria-controls` 제공
- 메뉴는 Escape로 닫히고 열기 버튼으로 포커스 복귀
- 긴 작업명은 시각적으로 말줄임하더라도 접근 가능한 전체 이름 유지
- 모든 버튼의 키보드 포커스 링 유지
- 색상만으로 Primary/완료/오류 상태를 구분하지 않음
- 모바일 터치 대상 최소 44×44px
- 글자 크기를 24px까지 키워도 헤더 요소가 겹치거나 잘리지 않도록 검증

## 10. 구현 순서

1. 현재 헤더 기능과 조건부 노출 규칙을 체크리스트로 고정한다.
2. `WorkspaceHeader` 컴포넌트를 생성하고 기존 callback을 그대로 연결한다.
3. 데스크톱 2단 grid 구조와 시각적 계층을 구현한다.
4. 태블릿에서 2~3행으로 안정적으로 재배치한다.
5. 모바일 사용자 메뉴/더보기 동작을 구현한다.
6. ModelStatus 팝오버와 사용자 메뉴의 z-index·위치·외부 클릭 동작을 조정한다.
7. 키보드, 스크린 리더 이름, 확대 및 긴 텍스트를 검증한다.
8. 회귀 테스트와 실제 화면 캡처 비교 후 간격을 조정한다.

- 1440×900, 1280×800, 1024×768, 768×1024, 390×844

- 진행 단계와 현재 작업명이 스크린 리더에서 명확히 전달
- 색 대비와 44px 터치 영역 확인

## 12. 완료 기준

- 1280px 이상에서 헤더 주요 영역이 의도하지 않게 줄바꿈되지 않는다.
- 현재 작업명과 진행 단계가 가장 먼저 인식된다.
- 문맥 동작과 전역 동작이 시각적으로 구분된다.
- 모바일에서 핵심 작업이 가로 스크롤 뒤에 숨지 않는다.
- 기존 헤더 기능과 튜토리얼 연결이 모두 유지된다.
- 긴 텍스트, 200% 확대, 앱 글자 크기 24px에서도 겹침이나 잘림이 없다.
- 키보드만으로 모든 헤더 기능을 사용할 수 있다.
- `npm run build`와 관련 컴포넌트 테스트가 통과한다.
